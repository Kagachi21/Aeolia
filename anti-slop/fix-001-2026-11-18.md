## Fix

Finding 1 — HIGH, R-25 Color Contrast — `src/settings/settings.css:338`.

Before: `.ap-clock` was hardcoded to `#e9eef7`. Only the `Translucent` preview overrode it to dark, so the live preview clock was near-white on the near-white `Liquid glass` and `Candy glass` pills.

After: `.ap-clock` uses `var(--set-text, #e9eef7)`. Each surface already defines `--set-text` at the root, so light surfaces inherit dark ink and dark surfaces keep light ink. No global ink rule was touched; the existing `Translucent` override remains harmless.

## Probe

Added `_probe-r16-settings-clock.js`. It opens the real Settings window, selects Appearance, resolves the computed ink through a 1x1 canvas, samples 44 painted pixels in a ring around the clock box, and computes WCAG contrast against the worst sampled pixel.

Before the CSS change: **2/4 PASS**
- Liquid glass: worst 1.007:1, median 1.105:1 — FAIL
- Candy glass: worst 1.238:1, median 1.272:1 — FAIL
- Translucent: worst 5.762:1 — PASS
- Black: worst 16.884:1 — PASS

After the CSS change: **4/4 PASS**
- Liquid glass: worst 11.593:1, median 14.494:1
- Candy glass: worst 8.659:1, median 10.334:1
- Translucent: worst 5.762:1, median 7.791:1
- Black: worst 16.804:1

The probe was run before the fix and failed for the expected reason, then after the fix and passed.
