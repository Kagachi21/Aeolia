# Native Content Parity uses a Golden Matrix

Native Content Parity will be proven with one Golden Matrix: a single explicit row per panel, state, transition, shortcut, notification path, settings change, external-service contract, and honest stub. Each row records the source pointer, exact user-visible strings, expected behavior outcome, trigger, fixture, and the native probe evidence. User-visible text must match the current working tree exactly; external services are tested through deterministic fixtures plus a recorded request/parse contract, not live network calls. Pixel matching is not required. Deck and Calls remain honest stubs with their existing inactive message. This trades flexibility for repeatable evidence because content/behavior drift would otherwise be judged subjectively.
